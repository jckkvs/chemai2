# ChemAI2 NiceGUIフロントエンド 作業指示まとめ

## 基本方針

### 1. アプリの核心
- **このアプリの目的は「解析」ではなく「意思決定」である**
- ユーザーが知りたいのは「次に何をすればいいか」ということ
- 次の実験を決める／目標の再設定／撤退判断がメイン機能

### 2. 使用技術
- NiceGUI v3.8.0（PythonベースのWeb UIフレームワーク）
- ダークテーマUI（gray-900背景、blue-600アクセント）
- ハッシュベースルーティング（#page_name）
- 状態管理: AppStateクラス（utils/__init__.py）
- Plotlyによるデータ可視化
- Pandasによるデータ処理

### 3. 既存資産の活用
- `uilegacy/` - 既存UIコンポーネント
- `chemai2_qwen/frontend_nicegui/components/` - 既存コンポーネント
- `backend/` - バックエンドモジュール（data_loader, eda, ml, doe等）

## UI設計指示

### 4. ユーザー目線でのシンプル化（最重要）
- **開発者向けのコメント・説明は一切削除する**
- エンドユーザーが本当に必要とする情報のみを表示
- 「ユーザーが最初に見たとき、何をどうすればいいのかわからない」ようなUIは不可
- バックエンドモジュールや科学計算エンジンの数をユーザーに見せる必要はない
- 「あったらいいな」ではなく「あったら絶対に必要」だけを表示

### 5. ナビゲーション構成
- **コアフロー（最重要）**: ウェルカム → データアップロード → EDA → 意思決定支援★
- **その他の機能（手段）**: LLMヒアリング、前処理、MLモデリング、実験計画法、結果・レポート
- 手段ページは目立たなくする（ナビゲーションから削除し、必要なときだけリンクからアクセス）

### 6. 各ページの方針

#### ウェルカムページ
- 「何ができるか」をユーザー視点で表示
- 4ステップフロー: アップロード → LLM対話 → EDA → 意思決定
- 技術仕様やエンジン一覧は削除

#### データアップロードページ
- シンプルに: アップロード → 目的変数選択 → EDAへ
- サンプルデータの利用を推奨

#### EDAページ（核心ページ）
- 「サンプル名を言われたら値がわかる」レベルまでデータを把握
- タブを絞る: 基本統計、可視化（フィルタリング・SMILESは削除）
- 意思決定支援へ進む導線を明確に

#### 意思決定支援ページ（★最重要★）
- **このアプリの核心**
- 達成確率を大きく表示（150px円グラフなど）
- 次にすべきアクションを明示
- 撤退判断を表示
- 他の操作（EDA、モデル学習、実験計画）は目立たなくする

#### MLモデリング・DOE・結果ページ（手段）
- **「意思決定のための手段」として最小化**
- 詳細設定（ハイパーパラメータ、単調性制約等）は削除
- 基本機能のみ: モデル学習→結果表示、実験計画→条件生成
- 保存モデル一覧、エクスポートオプション等は削除

#### 前処理ページ
- 基本的前処理オプションのみ
- 特徴量エンジンの詳細（RDKit、xTB等）は削除
- SMILESがある場合の特徴量計算のみ残す

#### LLMヒアリングページ
- 対話インターフェースのみ
- 採取されたドメイン知識の表示は削除

#### 設定ページ
- LLM設定、表示設定、ドメイン知識管理をタブで切り替え

## 起動方法

```bash
cd frontend_nicegui
python main.py
```

ブラウザで http://localhost:8080 を開く
